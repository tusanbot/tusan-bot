# Tosan Telegram Publisher

ربات مستقل انتشار خودکار محتوای وب‌سایت توسن در کانال اصلی تلگرام.

## تصمیم‌های قطعی محصول

- بدون هوش مصنوعی؛ عنوان، خلاصه و محتوای موجود در سایت عیناً مبنای پیام است.
- انتشار کاملاً خودکار و بدون صف تأیید مدیر.
- یک مقصد انتشار: کانال اصلی توسن.
- خبر، مقاله و آموزش با پیام HTML فارسی و لینک داخلی «ادامه مطلب».
- ثبت‌نام فعال با دکمه‌ی Inline Keyboard و لینک مستقیم درخواست.
- ویرایش پیام قبلی هنگام تغییر عنوان، خلاصه، شرایط یا مهلت.
- پس از پایان مهلت، نمایش «ثبت‌نام منقضی شده است» و حذف دکمه‌ی درخواست.
- جدیدترین ثبت‌نام فعال در میان ثبت‌نام‌های منتشرشده پین می‌ماند؛ با انقضا، پین به جدیدترین مورد فعال بعدی منتقل می‌شود.

## منبع محتوا و همگام‌سازی

پایش زمان‌بندی‌شده‌ی فعلی سایت، منبع حقیقت باقی می‌ماند و محتوا را در همان جداول Supabase درج یا به‌روزرسانی می‌کند. این ربات crawler یا سیستم تولید محتوای موازی ندارد.

پس از اعمال migration:
1. ربات روی تغییرات INSERT، UPDATE و DELETE جداول محتوای سایت از Supabase Realtime گوش می‌دهد.
2. هر تغییر، تطبیق منابع را فوراً اجرا می‌کند و عملیات لازم را در صف پایدار ربات قرار می‌دهد.
3. تغییرات صف نیز از Realtime دریافت می‌شوند و worker عملیات تلگرام را اجرا می‌کند.
4. تطبیق کامل منابع هر پنج دقیقه و بررسی صف هر سی ثانیه به‌عنوان مسیر بازیابی رویدادهای ازدست‌رفته اجرا می‌شود. برای ثبت‌نام‌ها، عملیات انتشار در زمان شروع و انقضا در زمان پایان در صف زمان‌بندی می‌شود؛ تغییر مهلت، عملیات زمان‌بندی‌شده‌ی قبلی را هنگام اجرا با داده‌ی تازه تطبیق می‌دهد.

جداول منبع:
- public.news_announcements: فقط موارد منتشرشده؛ رکوردهای ثبت‌نامی این جدول باید لینک رسمی اقدام داشته باشند.
- public.blog_posts: فقط موارد با status = 'published'.
- public.services_announcements: موارد type = 'registration'؛ زمان پایان مؤثر از extended_end_at و سپس end_at خوانده می‌شود. لینک مستقیم درخواست از رابطه‌ی service_id به services.slug ساخته می‌شود.

ثبت‌نامی که لینک مستقیم معتبر نداشته باشد منتشر نمی‌شود؛ پیام بدون دکمه جایگزین آن نخواهد شد.

در اولین راه‌اندازی، محتوای قدیمی سایت به‌صورت انبوه در کانال منتشر نمی‌شود: رکوردهای قدیمی خبر و مقاله به‌عنوان baseline نادیده‌گرفته‌شده ثبت می‌شوند؛ ثبت‌نام‌های فعال فعلی منتشر می‌شوند تا با انقضای جدیدترین مورد، مورد فعال بعدی برای پین‌کردن موجود باشد. هر محتوا یا ویرایشی که پس از زمان baseline ایجاد شود، طبق روال خودکار منتشر می‌شود.

## معماری

- **Source adapter**: خواندن سه جدول محتوایی موجود.
- **Realtime + reconciliation**: دریافت تغییرات فوری و بازیابی دوره‌ای.
- **Durable queue**: ذخیره‌ی عملیات، کلید یکتای رویداد و retry.
- **Telegram API client**: ارسال، ویرایش، دکمه، pin و unpin.
- **Publication state**: نگهداری شناسه‌ی پیام، هش محتوا، وضعیت و تاریخچه.
- **Operations**: لاگ، بازیابی پس از restart و کنترل خطا.

## محدودیت تضمین ارسال تلگرام

Telegram Bot API برای sendMessage کلید idempotency ارائه نمی‌کند. اگر اتصال بعد از ثبت پیام در تلگرام و پیش از دریافت پاسخ قطع شود، نتیجه مبهم است. برای جلوگیری از پیام تکراری، چنین ارسال مبهمی خودکار تکرار نمی‌شود و در صف به وضعیت dead/uncertain می‌رود تا بررسی شود. عملیات ویرایش، انقضا و پین قابل retry هستند.

در این نسخه اجرای یک نمونه‌ی worker توصیه می‌شود؛ claim صف به‌صورت compare-and-set انجام می‌شود، اما هماهنگی هم‌زمانی عملیات پین بین چند نمونه هنوز نیازمند تکمیل است.

## زمان و تاریخ

- منطقه‌ی زمانی نمایشی: Asia/Tehran.
- زمان‌های پایگاه داده با timestamp مطلق (UTC) نگهداری می‌شوند.
- تاریخ‌های پیام با تقویم فارسی و منطقه‌ی زمانی تهران نمایش داده می‌شوند.

## راه‌اندازی

نیازمندی: Node.js نسخه‌ی 22.11 یا جدیدتر.

1. فایل .env.example را به .env کپی و مقادیر را تکمیل کنید.
2. migration موجود در db/migrations/001_telegram_publisher_state.sql را بازبینی و سپس روی پروژه‌ی Supabase اعمال کنید.
3. وابستگی‌ها را نصب کنید و بررسی‌ها را اجرا کنید:

```bash
npm install
npm run typecheck
npm test
npm run build
npm start
```

## متغیرهای محیطی

- TELEGRAM_BOT_TOKEN: توکن BotFather؛ محرمانه.
- TELEGRAM_CHANNEL_ID: شناسه یا username کانال مقصد.
- SUPABASE_URL: آدرس پروژه‌ی Supabase توسن.
- SUPABASE_SERVICE_ROLE_KEY: فقط سمت سرور؛ هرگز در مخزن یا کلاینت عمومی قرار نگیرد.
- SITE_URL: دامنه‌ی اصلی سایت.
- NEWS_URL_TEMPLATE: قالب URL عمومی خبر با placeholder برابر {slug}.
- SERVICE_REQUEST_URL_TEMPLATE: قالب URL مستقیم درخواست خدمت با placeholder برابر {slug}.
- SOURCE_POLL_INTERVAL_MS: فاصله‌ی تطبیق کامل منابع؛ پیش‌فرض 300000.
- QUEUE_POLL_INTERVAL_MS: فاصله‌ی بررسی بازیابی صف؛ پیش‌فرض 30000.
- QUEUE_BATCH_SIZE: تعداد عملیات در هر نوبت؛ پیش‌فرض 10.

مسیر درخواست خدمت در سایت بررسی شد و الگوی آن /services/{slug} است. مسیر مقاله وبلاگ /blog/{slug} نیز موجود است. در نسخه‌ی فعلی مخزن وب‌سایت route عمومی جزئیات خبر با slug پیدا نشد؛ بنابراین تا زمان تعیین یا ایجاد آن، NEWS_URL_TEMPLATE اختیاری است و خبرهای عادی بدون لینک داخلی منتشر نمی‌شوند. این خبرها در baseline ثبت می‌شوند تا با فعال‌کردن مسیر در آینده، آرشیو قدیمی ناخواسته منتشر نشود. ثبت‌نام‌های دارای لینک مستقیم رسمی همچنان قابل انتشارند.
